概念 01｜為什麼需要 FHIR？

打破醫院之間的「資訊孤島」

❌ 過去：各講各的方言

  • 每家醫院的資訊系統（HIS）資料格式都不同。
  • A 醫院的檢驗報告，B 醫院的電腦無法直接讀取。
  • 病人跨院轉診只能靠光碟或紙本，容易重複檢查。

✅ 現在：FHIR 共通語言

  • 全名：Fast Healthcare Interoperability Resources。
  • 由國際醫療標準組織 HL7 制定。
  • 讓醫院、診所、手機健康 App 都能用同一套標準安全交換資料。
概念 02｜核心架構

醫療界的樂高積木：Resource（資源）

💡 白話比喻：FHIR 把複雜的病歷拆成一塊塊標準化的「樂高積木」，每一塊積木就叫一個 Resource，各自負責記錄一種特定資訊，需要時再自由組裝起來。

🧑 Patient（病人）

記錄基本身分資料：姓名、性別、出生年月日、聯絡電話與地址。

🩺 Observation（觀察檢驗）

記錄量測與檢驗數值：血壓（120/80 mmHg）、血糖、體溫、抽血報告。

💊 MedicationRequest

記錄醫師開立的用藥處方：藥品名稱、劑量與每日服用頻率。

概念 03｜資料怎麼傳？

採用現代網頁技術：RESTful API 與 JSON

傳統醫療標準語法極度艱澀；FHIR 直接借用現代網站開發最普及的工具，讓工程師能快速串接。

🌐 RESTful API（傳輸動作）

就像瀏覽網頁一樣，用標準 HTTP 指令溝通：

  • GET：查詢某位病人的檢驗報告
  • POST：新增一筆掛號或生理量測紀錄

📄 JSON（資料格式範例）

{
  "resourceType": "Patient",
  "id": "example-01",
  "name": [{ "text": "王小明" }],
  "gender": "male"
}
概念 04｜台灣在地化

台灣醫療現場應用：TW Core IG

🇹🇼 為什麼需要台灣版？國際版 FHIR 沒有「身分證字號」或「健保卡號」欄位，因此衛福部制定了 TW Core IG（台灣核心實作指引），讓國際標準符合台灣醫療法規與健保制度。

🏥 跨院電子病歷

轉診時授權調閱他院檢查影像與用藥紀錄，免去重複抽血。

📱 健保快易通

民眾能在手機上即時查詢個人就醫與檢驗結果。

👵 長照與居家照護

讓醫院出院準備資料無縫銜接至長照機構與居家護理。

概念 05｜智慧醫療與 AI

讓醫院像手機一樣裝 App：SMART on FHIR

📱 手機 App Store 概念

醫院的資訊系統就像 iOS / Android 作業系統。只要支援 SMART on FHIR，醫院就能像下載 App 一樣，直接外掛各種第三方 AI 輔助診斷工具，不用每次都重寫底層程式。

🔒 OAuth 2.0 隱私保護

結合現代網路安全授權協定，外部 AI 工具只能在獲得醫生與病人授權的情況下，讀取「完成判讀所需的最少病歷片段」，確保資料不外洩。

快速複習

一張表看懂 FHIR 五大核心重點

  • 解決痛點（條目 01）：消除醫院間的資訊孤島，建立全球共通醫療語言。
  • 資料單元（條目 02）：以 Resource 為最小樂高積木（如 Patient、Observation）。
  • 傳輸技術（條目 03）：採用現代網頁標準 RESTful API 與輕量的 JSON 格式。
  • 台灣落地（條目 04）：衛福部推動 TW Core IG，納入健保與本土醫療欄位。
  • AI 擴充（條目 05）：透過 SMART on FHIR 讓醫院安全外掛智慧醫療應用程式。
